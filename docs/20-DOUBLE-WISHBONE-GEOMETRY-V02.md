# Double-Wishbone Geometry Solver v0.2

Status: implementation specification
Updated: 2026-09-23

## 1. Purpose
Replace damaged-suspension lookup approximations with a real 3D geometric solve.

The first target is the TA-P01 front double-wishbone corner.

## 2. Geometric representation

Fixed/runtime chassis-side pickups:
- upper arm inner A;
- upper arm inner B;
- lower arm inner A;
- lower arm inner B;
- tie-rod inner.

Rigid upright reference points:
- upper ball joint;
- lower ball joint;
- tie-rod outer;
- wheel center.

The upright reference tetrahedron is rigid. Suspension motion comes from the wishbone and tie-rod constraints.

## 3. Constraint set

Upper ball joint:
```
|U - UpperInnerA| = reference
|U - UpperInnerB| = reference
```

Lower ball joint:
```
|L - LowerInnerA| = reference
|L - LowerInnerB| = reference
```

Tie rod:
```
|T - TieRodInnerRuntime| = reference
```

Rigid upright:
```
|U-L|
|U-T|
|L-T|
|U-W|
|L-W|
|T-W|
```
remain equal to their reference lengths.

Travel constraint:
```
W.z = W_reference.z + Travel
```

Positive travel = bump/compression.

## 4. Why this representation
The four unknown upright points contain 12 scalar DOF.

The complete constraint set plus target travel resolves the mechanism while:
- preserving full 3D geometry;
- allowing steering through tie-rod inner displacement;
- allowing structural damage through chassis-pickup displacement;
- avoiding hard-coded camber/toe damage multipliers.

## 5. Steering
The runtime tie-rod inner point is:
```
TieInnerRuntime =
TieInnerReference
+ StructuralOffset
+ RackAxis * RackDisplacement
```

Rack displacement therefore changes solved upright orientation rather than directly setting wheel angle.

## 6. Structural damage
Each chassis-side pickup has its own runtime structural offset:
```
P_runtime = P_reference + DamageOffset
```

Initial implementation supports chassis-pickup displacement.

Later:
- bent arm effective geometry;
- bent tie rod;
- upright deformation;
- bearing play.

## 7. Solver
Prototype uses iterative positional projection.

Unknown points:
```
U, L, T, W
```

Per iteration:
1. project U to upper-inner A distance;
2. project U to upper-inner B distance;
3. project L to lower-inner A distance;
4. project L to lower-inner B distance;
5. project T to tie-inner distance;
6. project all six rigid-upright pair distances;
7. project W to target travel Z.

The solver begins from:
- previous valid solution if available;
- otherwise reference geometry translated by requested travel.

## 8. Convergence
Config:
- maximum iterations;
- position tolerance;
- valid travel range.

Output:
- converged flag;
- iterations used;
- maximum constraint residual.

A solution outside tolerance must never silently be treated as valid cached geometry.

## 9. Upright orientation
A rigid basis is reconstructed from reference and solved upright triangles.

Reference/current basis:
- primary axis = lower → upper ball joint;
- secondary axis = tie-rod direction projected perpendicular to primary;
- tertiary = cross product.

Reference wheel vectors are mapped through that basis:
- wheel forward;
- wheel right/axle;
- wheel up.

The wheel center comes directly from solved W.

## 10. Alignment
Toe:
signed projected angle between chassis +X and solved wheel-forward direction around chassis +Z.

Camber:
signed angle between chassis +Z and solved wheel-up direction around solved wheel-forward direction.

Exact sign convention is locked by tests:
- toe-right/left uses a chassis-local yaw sign;
- negative camber means tire top inward.

## 11. TA-P01 seed geometry
Initial hardpoints are engineering seeds only, chosen to be geometrically plausible for a compact sports coupe.

They are not measured OEM geometry and must not be represented as such.

## 12. Damage-mode switching
Undamaged:
```
precomputed cache
```

When pickup displacement exceeds tolerance:
```
cache invalid
→ runtime geometric solver
```

When repaired/restored to authored geometry, cache may become valid again after verification.

## 13. Required tests
- reference travel/rack solve converges;
- reference solution reconstructs wheel center closely;
- bump travel changes wheel center continuously;
- rack movement changes toe;
- upper/lower pickup displacement changes alignment;
- left/right mirrored geometry remains mirrored;
- impossible/degenerate geometry is rejected;
- solver residual remains bounded.

## 14. Performance
Runtime damaged geometry is expected only for a small number of nearby/high-fidelity vehicles.

Undamaged vehicles continue to use precomputed kinematics.

This is an explicit physics-LOD optimization.

## 15. Acceptance
v0.2 passes when:
- front geometry converges through the valid travel range;
- steering is generated by tie-rod geometry;
- structural pickup offsets alter alignment naturally;
- wheel center/orientation can feed tire/contact calculations;
- no arbitrary damaged-toe/camber multiplier is required.
